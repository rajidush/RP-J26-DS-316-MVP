# Evaluation (Milestone A4)

CPU-only measurement of the C2 text cascade: accuracy, false positives,
latency and RAM. Everything routes through the same scorer interface, so an
ablation, a candidate model and the shipped cascade are measured by identical
code — no private path can flatter one of them.

## Files

| File | What it is |
|---|---|
| `dataset.py` | **Development set** (68 cases). The detectors were designed against it. |
| `heldout.py` | **Held-out set** (40 cases). Written after the detectors, never tuned on. |
| `benchmark.py` | The harness. |
| `accuracy_report_dev.md` | Generated — dev-set results. |
| `accuracy_report_heldout.md` | Generated — held-out results. **Quote this one.** |
| `baseline_extract.md` | OCR/ASR/CLIP notes (Steps 2–4). |
| `demo_e2e_report.md` | Generated by `python -m analyst.demo_e2e`. |

## Running it

```powershell
python -m analyst.evaluation.benchmark --corpus heldout --compare
python -m analyst.evaluation.benchmark --corpus dev --sweep
python -m analyst.evaluation.benchmark --corpus heldout --hf unitary/toxic-bert
```

`--compare` runs every registered scorer, `--sweep` prints a threshold sweep,
`--hf MODEL_ID` benchmarks any HuggingFace text-classification model (repeatable),
`--json` emits machine-readable output.

## Reading the numbers honestly

**Two corpora, and they do not mean the same thing.** The lexicon pattern
families were written from dev-set failures, so dev results measure fit, not
skill. The cascade scores 100% on dev and 67.5% held out — the gap *is* the
overfitting, and it is the honest headline.

| Scorer | dev acc | held-out acc | held-out recall |
|---|---|---|---|
| `lexicon` only | 94.0% | 52.5% | 5.0% |
| `cascade` (shipped) | 100.0% | **67.5%** | **40.0%** |
| `toxic-comment-model` (previous default) | 58.2% | 50.0% | 5.0% |

The lexicon collapsing from 94% to 5% recall held out is the clearest evidence
that pattern matching cannot carry semantics; the models supply the
generalisation, and the lexicon supplies precision and auditability.

**Accuracy is not the primary metric.** For a tool that interrupts a child,
false positives in `gaming`, `reporting` and `figurative` matter more: a wrong
alert teaches the child that ordinary play, or asking an adult for help,
triggers surveillance. Those buckets are reported separately and are the first
thing to check after any change.

## Known gaps (measured, not hidden)

Held out, the cascade scores **0% on threats and 0% on sexual harassment**
phrased in words the patterns do not contain, and 60% on implicit identity
hate. Both pretrained heads score near zero on implicit peer harm without
profanity — they are trained on corpora where toxicity correlates with slurs.

That is the empirical case for Milestone A3/A4 fine-tuning: **pretrained hate
and toxicity models do not transfer to implicit, context-dependent peer harm
typical of children's interactions.** These numbers are the pretrained baseline
that fine-tuned models get compared against.

`unalive yourself` in `heldout.py` is a deliberate known failure — platform
evasion slang the lexicon does not know. It documents a gap rather than hiding
one; do not fix it by adding the literal string.

## Rules for changing the sets

1. Held-out cases are written from the *concept*, before running them.
2. A held-out failure is fixed in the detector only if it is a genuine class of
   harm — never by adding the failing string to a pattern.
3. If a held-out case is ever used to tune a rule, move it to `dataset.py` and
   write a replacement.

All numbers: reference CPU machine, CUDA disabled. Generated reports are
overwritten on each run.
